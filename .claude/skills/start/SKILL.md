# Skill: Start Session

## Что делать

1. **Прочитать слои памяти** — обе оси (контракты + state):

   **Контракты (что должно быть):**
   ```
   Read .claude/ARCHITECTURE.md   (если есть)
   Read .claude/INVARIANTS.md     (если есть — нарушения = баг, не предпочтение)
   ```

   **State (что есть сейчас):**
   ```
   Read .claude/SNAPSHOT.md       (точка работы)
   Read .claude/BACKLOG.md        (если есть — план Next/Soon/Later)
   ```

   Если какие-то слои отсутствуют — это OK для старого проекта; но если они отсутствуют в новом v6.2+ проекте, это сигнал что установка неполная. Не паниковать, продолжить.

2. **Прочитать CLAUDE.md** — контекст проекта:
   ```
   Read CLAUDE.md
   ```

3. **Проверить git status:**
   ```bash
   git status --short
   git log --oneline -5
   ```

4. **Проверить версию фреймворка** (фоново, не блокирует старт):
   ```bash
   # Проверить версию фреймворка в README.md или manifest
   grep -m1 'v[0-9]' README.md 2>/dev/null || true
   ```
   Если в проекте указан remote для шаблона — можно проверить latest release. Не блокировать работу.

5. **Создать лог сессии:**
   ```bash
   mkdir -p .claude/logs/sessions
   ```
   Создать файл `.claude/logs/sessions/YYYY-MM-DD_HH-MM.md` с начальным состоянием (timestamp, SNAPSHOT status, git status).

6. **Доложить пользователю** (кратко, 3-5 строк):
   - Статус проекта (из SNAPSHOT)
   - Что было сделано в прошлой сессии
   - Незавершённые задачи (из BACKLOG.Next, если есть)
   - Открытые инварианты, которые могут быть затронуты задачей (если задача очевидна)
   - Готовность к работе

## Чего НЕ делать

- Не показывать содержимое файлов пользователю
- Не запускать тесты (это делает `/finish`)
- Не коммитить (если есть незакоммиченное — сообщить, не коммитить автоматически)
- Не тратить больше 30 секунд на инициализацию

## После выполнения

Агент готов принимать ТЗ от пользователя.
