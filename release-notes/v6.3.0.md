# Claude Code Starter v6.3.0

## Summary

Minor release that embeds the **orchestrator model** into the framework — a conceptual shift in who runs production, distilled (like v6.2.x before it) from field experience in the Saved Downloader project and from comparing agent-orchestration setups across tools.

**Before v6.3.0** the framework's implicit model was flat: the agent is a "project manager" with subagents, and the *owner* personally launches every parallel worker session, pastes handoffs between them, and acts as the integration bus.

**From v6.3.0** the default model is three-level:

```
OWNER         product / methodologist ABOVE production:
              goal + authority envelope + outcome review + stop-point decisions
ORCHESTRATOR  the agent in the lead session: decomposes work into streams,
              spawns its OWN workers, integrates, verifies, commits
WORKERS       ephemeral executors in their own fresh contexts
              (subagents / isolated git worktrees / deterministic workflows);
              invisible to the owner
```

The owner stays in the product seat. The agent runs production — and wakes the owner only at stop-points: production deploys, external effects, irreversible actions, runtime-data deletion.

The second axis of the same change is **continuity**: context must survive session changes without drowning the next session. Cross-session continuity is carried by the bounded two-axis memory (contracts ⟂ state) plus a thin, verifiable handoff pointer — never by an ever-growing context megafile. A continuity file that grows without bound is a bug: it drowns the very session it was meant to save.

## What's New

### `orchestration-model.md` — portable rule set, now shipped

`templates/global/rules/orchestration-model.md` is installed into `~/.claude/rules/` by `install-global.sh`. Twelve principles (O1–O12), the load-bearing ones:

| Principle | Essence |
|---|---|
| O1 Owner above production | Owner's input: green spec + authority envelope + review + stop-decisions. Never ask the owner to play dispatcher or bus. |
| O2 Map vs territory | Orchestrator holds the map (seams, contracts, stream states); workers hold the territory in their own contexts and return conclusions. |
| O3 Single writer | Shared contracts (schema / API / migrations / CI / entrypoints) have one assigned writer — enforced physically by worktree isolation, not by discipline. |
| O4 Judgment ⟂ bookkeeping | Worker models judge; deterministic code counts, dedupes, orders, and aggregates. |
| O5 Charter | The unit of worker control: goal, sources of truth, expected output, allowed actions, verification commands, stop conditions. No charter → read-only reconnaissance only. |
| O6 Four evidence statuses | `passed / failed / not_run / inconclusive`; the last two are never renamed optimistically. The verifier is independent and never fixes its own findings. |
| O7 Authority envelope | Minimal permissions; hard stops on the irreversible. |
| O8 Durability | Frequent atomic commits + separated project memory + resumable journals — the orchestrator's context window is not the source of truth. |
| O9 Intent → primitive | Cheapest working primitive wins: subagent before workflow, workflow before remote/cron. |
| O10 Fan-out vs solo | Decomposable / coverage / parallel writers → fan out. Coherence-critical authoring → solo. Knowing when *not* to fan out is part of the judgment. |
| O11 Legacy path | Wrap the manual handoff model, don't tear it down: move "launch a worker" from owner to orchestrator one stream at a time. |
| O12 Bounded continuity | Separate bounded memory layers + thin handoff pointer; unbounded continuity files are bugs. |

### `/handoff` skill — now in the install set

`templates/global/skills/handoff/` ships with the framework and is installed by `install-global.sh`. Previously the global addendum *referenced* `/handoff` while the skill only existed in the author's personal global layer — a dangling reference for every fresh install. Fixed.

The skill is the carrier of the continuity axis: role-typed session handoffs (orchestrator / executor / reviewer / owner / general), grounding discipline (verify claims against the territory before writing them), and a verification-report handshake for accepting a new session's understanding.

### `autonomy.md` evolved

New section «Оркестраторская модель: владелец над производством» — the three-level frame stated explicitly, with the "don't pull the owner in" rule extended to the whole production layer: spawning workers, integration, and commits need no confirmation.

### `delegation.md` evolved

New section «Оркестрация: charter, веер/solo, один писатель, доказательства» — charters for writing workers, fan-out vs solo judgment, single-writer-via-worktree, four evidence statuses, deterministic multi-worker graphs via saved workflows.

### `CLAUDE.addendum.md` updated

The global-layer addendum documents the orchestrator model (v6.3.0+ section) so merged global `CLAUDE.md` files carry the three-level frame and its five key operating rules.

## Why this matters

Every prior version assumed the owner personally launches and glues worker sessions. That was correct when only a human could open a session. It no longer is: the agent can spawn, isolate, budget, and resume workers programmatically. v6.3.0 moves the framework's default to that reality — expensive human attention goes only where it is genuinely needed: goals, priorities, risk, stop-points.

## Upgrade Notes

- All changes are **additive**. `install-global.sh` adds `orchestration-model.md` and `/handoff` only if absent; customized copies are never overwritten.
- Existing projects keep working under the flat model until adopted; O11 defines the incremental legacy path (wrap, don't rewrite).
- No changes to installer flags, project detection, memory layers, or dialog preservation.

## Compatibility

Backward compatible with all v6.x and v5.x installer flags. Existing projects migrate cleanly.
