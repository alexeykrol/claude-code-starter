# Claude Code Starter v6.2.1

## Summary

Patch release driven by a second user case report (`FRAMEWORK-CASE-ONBOARDING.md`) from the Saved Downloader project. Same reporter who flagged the v6.2 memory-axis regression now identifies three structural defects in session-onboarding protocols:

1. **Duplicate of the auto-loaded CLAUDE.md** — two sources of truth, inevitable drift
2. **Cap on report length** — read by the model as ceiling on depth, not floor on brevity
3. **Map without territory** — reading only metafiles inherits the project's self-description blind spots

Our `/start` skill had defects 2 and 3 verbatim. This patch fixes both and guards against defect 1.

- `init-project.sh`
- `framework.tar.gz`
- `checksums.txt`
- `RELEASE_NOTES.md`

## What's Fixed

### `/start` skill rewritten

**Removed:** "Доложить пользователю (кратко, 3-5 строк)". The user's report documents this exact phrase being read as a ceiling on understanding, not a floor on verbosity — agent builds the smallest model sufficient for 5 lines and stops, even when asked to genuinely analyze the project.

**Added (depth scales to request):**

| User request | Report shape |
|--------------|-------------|
| Routine start / silent invocation | Compact: status, last session, open BACKLOG.Next, INVARIANTS in play, readiness — 5–10 lines |
| "Разберись с проектом", "проанализируй" | Full analytical breakdown: purpose, structure (modules/layers/contracts), map-vs-territory table from the grounding step, state, risks, knowledge boundaries — length follows the topic, not the format |
| Concrete task in first message | State + explicit linkage to the task |

Minimum is a floor of adequacy. No ceiling.

**Added (grounding step):**

Mandatory step between reading metafiles and reporting — `git log --oneline -10`, `wc -l` across main directories, `grep` for `TODO/FIXME/raise NotImplementedError`. Discrepancies between SNAPSHOT/ARCHITECTURE claims and grep/wc reality are reported explicitly, not smoothed over.

**Added (explicit boundary marker):**

After `/start` you know the **map**, not the **territory**. Before editing a subsystem, read its code and local docs. The danger isn't an incomplete model — it's false confidence in its completeness.

### CLAUDE.md templates — new "Назначение этого файла" section

Code and content templates get a header that explicitly distinguishes **three kinds of constraints**:

| Kind | Where | How to treat |
|------|-------|--------------|
| On actions | `INVARIANTS.md`, `production-safety.md` | **Hard** — guardrails |
| On attention | reading order, two memory axes | **Helpful** — structure makes depth achievable in finite context |
| On depth/output | — | **None** — depth is dictated by the user's request, not the protocol |

The point: no future "let's keep starts brief" edit can quietly reintroduce a depth cap.

### `validate-release.sh` — onboarding-file guard

Release fails if any `ONBOARDING.md` ships in `templates/` or `.claude/`. Constitution must live only in `CLAUDE.md` (which the harness auto-loads). A parallel onboarding file inevitably drifts.

### Methodology draft recorded

`methodology/draft/onboarding-protocols-must-not-cap-depth.md` captures the case so the framework remembers why. Linked to the v6.2 memory-axes draft — same reporter, same project, second observation in the same shape. Pattern in formation per the methodology ladder.

## Upgrade Notes

The installer detects v6.2.0 as `upgrade` and runs additive migration:
- `.claude/skills/start/SKILL.md` is replaced if it hasn't been manually edited; edited versions are preserved with a backup
- `CLAUDE.md` "Назначение" section is added via the same Python merger as v6.2.0 — existing custom content is preserved

No data loss expected.

## Compatibility

Backward compatible with all v6.x and v5.x installer flags. Existing projects migrate cleanly.
